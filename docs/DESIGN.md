# st-chat-lobby — 채팅 로비 설계

> 대상: SillyTavern `staging` @ `bc81b9f7e` (2026-10-03). 라인 번호는 이 커밋 기준.

## 0. 한 줄 요약

시작 화면(`.welcomePanel`)이 `#chat`에 붙을 때마다 ST 최근 채팅 목록을 **숨기고**(지우지 않음) 그 자리에
전체 채팅 목록을 넣는다. 같은 목록을 마법봉 메뉴의 창(`POPUP_TYPE.DISPLAY`)으로도 연다.
목록은 `/api/chats/recent`를 **개수 제한(`max`)**으로 한 번 불러오고, 검색·필터·정렬은 클라이언트에서 한다.

## 1. 참고한 확장

| | Chat_list (IllIlIlIlllIII) | ChatPlus2 (SoFizzticated) |

| 가져온 것 | 시작 화면 자리 교체, 날짜 묶음 제목, 메시지 수·용량 | 이름·내용까지 검색, 선택 모드 일괄 삭제, 아바타 키(배열 번호 X), 열기 전 존재 확인 |
| 피한 것 | 그룹 삭제가 없는 경로(`DELETE /api/chats/group`) 호출, 캐릭터마다 요청 2번, 30px 버튼 | 캐릭터 메시지 수 필드 오류(`chat_size`), 그룹 채팅 파일 전체 내려받기, 무제한 병렬 요청 |

두 확장 모두 그룹 채팅 삭제 뒤 `group.chats`/`editGroup`을 갱신하지 않는다 → 여기서는 갱신한다.

## 2. 데이터

- `POST /api/chats/recent { max, pinned: [] }` (`src/endpoints/chats.js:1054`)
  - 서버는 캐릭터 폴더·그룹 정의·채팅 폴더 루트의 `.jsonl`을 **stat 만** 해서 수정 시각 순으로 정렬 → 앞의 `max`개만 `getChatInfo`(파일을 끝까지 읽어 줄 수·마지막 메시지)
  - 그래서 `max`가 서버 비용과 화면 비용을 함께 줄인다. 전체 개수는 돌려주지 않으므로 `limit + 1`개를 요청해 '더 있음'을 판단
  - 응답: `{ file_name, file_size, chat_items, mes, last_mes, avatar | group }`. 빈 채팅의 `mes`는 `'[The chat is empty]'` → `chat_items === 0`이면 미리보기를 비운다
  - 주인 없는 채팅(루트 파일, 삭제된 캐릭터)은 ST 시작 화면처럼 뺀다
- 정렬은 `last_mes` 기준(ST 시작 화면과 같음). 서버의 자르기는 파일 수정 시각 기준이라 둘이 다를 수 있지만 거의 같다
- 검색 대상은 주인 이름·채팅 이름·**마지막 메시지**(응답의 `mes`)뿐. 대화 중간 메시지까지 찾으려면 채팅 파일 전체를 읽어야 한다(`/api/chats/search`는 캐릭터·그룹 하나 단위)
- 검색 결과는 날짜·캐릭터 제목 대신 **찾은 곳**으로 묶는다(2026-10-03 사용자 요청): 모든 낱말이 주인 이름에 있으면 '캐릭터·그룹 이름', 주인+채팅 이름으로 되면 '채팅 이름', 마지막 메시지가 필요하면 '마지막 메시지'. 한 채팅은 한 묶음에만, 묶음 안은 고른 정렬 순서. 찾은 글자는 `<mark>`(텍스트 노드로만 조립), 마지막 메시지에서 찾은 경우만 미리보기를 찾은 글자 근처부터 보여 준다(두 줄 제한이라 안 보일 수 있음)
  - 계기: 'seraphina' 검색에 Sarah·Lily 채팅이 섞여 '전체가 나온다'로 보였다. ST 는 채팅 이름에 생성 당시 캐릭터 이름을 넣고, 이름 변경·카드 복사 후에도 그대로라 옛 이름이 채팅 이름에 남는다
- **묶음 접기**(2026-10-03 사용자 요청: 채팅이 많으면 스크롤이 번거로움): 모든 묶음(날짜 `date:*`, 캐릭터 `owner:*`, 찾은 곳 `found:*`)에 key, 제목은 `<button aria-expanded>`(sticky, 44px). 접은 묶음은 줄을 만들지 않고, `getVisibleChats`(모두 선택)에서도 뺀다(안 보이는 채팅을 지우지 않도록). 접은 상태는 목록이 떠 있는 동안만 기억. 위에 붙은 제목을 눌러 접으면 제목이 화면 밖으로 밀리므로 `scrollIntoView({ block: 'nearest' })`
- **대화 내용 검색**(별도 버튼, 같은 날 요청): 일반 검색에 섞지 않는다 — 서버가 채팅 파일을 끝까지 읽어 느리고, 글자마다 돌면 휴대폰이 버벅인다
  - 캐릭터·그룹마다 `POST /api/chats/search { query, avatar_url | group_id }`, 3개씩 동시. 서버 규칙: 낱말이 모두 (서로 다른 메시지여도) 메시지에 있거나 채팅 이름에 있으면 맞음. 어느 메시지인지는 안 알려 줌
  - 찾은 채팅 중 이름·마지막 메시지로 설명이 안 되는 것만 채팅 파일 전체(`/api/chats/get`, `/api/chats/group/get`)를 받아 '찾은 메시지'(모든 낱말이 든 첫 메시지, 없으면 낱말이 가장 많은 메시지)를 찾는다. 2개씩, 최대 `SNIPPET_LIMIT`(100)
  - 결과는 불러온 채팅과 key 로 합친다. 안 불러온 채팅도 목록에 끼우고(`getCandidates`), 이름·마지막 메시지에서 맞으면 그 묶음, 아니면 '대화 내용' 묶음
  - `AbortController`로 멈추기. 검색어가 바뀌면 버리고, 목록이 화면에서 사라지면(채팅 열림) 멈춘다. 진행 중 결과는 200ms 모아 다시 그린다
  - 확인: 중간 메시지의 'pineapplequartz'(마크다운 `*…*` 안), 불러온 개수 1개일 때 안 불러온 옛 채팅의 '이탤릭'(한글) → '대화 내용' 묶음 + 찾은 메시지 미리보기, 검색어 바꾸면 결과 사라짐, 멈추기
- **사용성 점검 후 1·2번(2026-10-03)**
  - 검색 범위 단순화: 검색 범위가 넷(불러온 N개 / 모든 채팅에서 검색 / 대화 내용 / 캐릭터)이라 '불러왔다'는 개념을 사용자가 알아야 했다. 이제 검색어가 있거나 정렬이 오래된·이름·메시지 수면 **자동으로 전체 채팅**(`getAllChats(0)`, 목록마다 한 번 받아 재사용 = `allChats`, 받는 동안은 최근 채팅 + '모든 채팅에서 찾는 중…'). 최근 순·캐릭터별은 정렬이 기억되므로 열 때마다 전부 받지 않도록 둘러보기(최근 N개 + 더 불러오기) 유지. '모든 채팅에서 검색' 카드·'불러온 N개 안에서' 안내·'(50+)' 제거(전체 개수를 알 때만 표시). 최근 목록이 이미 전부면 같은 배열을 쓴다(삭제 시 함께 갱신). 이름 바꾸기·삭제는 chats·allChats·ownerChats·대화 내용 결과 모두에 반영
  - 채팅 줄 압축: 휴대폰 한 화면에 3~4개(약 120px)뿐이었다(✎🗑가 폭을 차지해 이름이 2~3줄로 접힘, 날짜 중복, 메타 줄). 세 줄(주인·열림 배지·날짜 / 채팅 이름 한 줄 … + 💬 메시지 수 / 미리보기 한 줄)로 약 71px, 한 화면 약 6~7개. ✎🗑는 '⋮'(44px 폭, 줄 높이 전체) 뒤로 — 누르면 줄 아래에 정보(이름·메시지 수·용량) + [채팅 이름 바꾸기] [삭제](44px) 펼침, 한 번에 하나. 스크롤 중 삭제 오터치도 줄어든다
- **'있으면 좋은 것' 정리(2026-10-03, 1·2 → 4 → 3 → 5)**
  - 위쪽 도구: 캐릭터·정렬 줄을 [필터] 패널로 접음(설정 `filtersOpen`, 기본 접음). 접혀 있을 때 기본값에서 바꾼 것만 요약 줄 + 버튼에 점, ✕ 로 초기화(정렬도 'recent'로 저장). 아이콘만 있던 선택(☑)·새로 고침(⟳)은 글자 버튼으로, 새로 고침은 패널 안으로
  - 두 줄짜리 줄(compact): 캐릭터를 골랐거나 '캐릭터별' 묶음 안(`section.key` 가 `owner:`)에서는 아바타·캐릭터 이름을 빼고 1줄 채팅 이름·날짜, 2줄 페르소나·메시지 수·미리보기(페르소나를 1줄에 두면 긴 채팅 이름에 밀려 '♥…'만 남음). 약 52px
  - 캐릭터 고르기: 채팅 있는 주인만(캐릭터 `chat_size > 0`, 그룹 `chats.length`, 페이지 연 뒤 첫 대화는 불러온 채팅으로 보충), 최근 대화 순(`date_last_chat` 와 불러온 채팅의 최신 시각 중 큰 것), 채팅 수는 그룹은 바로·캐릭터는 전체를 알 때만(최근 목록이 전부이거나 `allChats`). 대화 내용 검색 대상도 같은 목록(채팅 없는 캐릭터를 돌지 않음)
  - 대화 내용 검색 진행: '3 / 5' → '3개 찾음 · 캐릭터 4명 중 3명 확인'(그룹이 있으면 '캐릭터·그룹 N곳', 찾은 메시지 단계는 '찾은 메시지 N개 중 M개 불러옴'), 한 곳만 찾을 때는 숫자 없이 막대만
- **고정 페르소나 표시**(2026-10-03 사용자 요청, '채팅에 고정된 페르소나'로 확인): 캐릭터 이름 옆에 '♥ 이름'(`chat_metadata.persona` → `power_user.personas`, 삭제된 페르소나면 파일 이름). `/api/chats/recent`·`/api/characters/chats`에 `metadata: true` — 서버는 첫 줄만 읽어 비용은 작지만 채팅 정보 전체가 오므로 응답이 조금 커진다(이 환경 9.3KB → 12.7KB). 그룹을 골랐을 때(`/api/chats/search`)와 대화 내용 검색 결과만 있는 채팅은 채팅 정보가 없어 표시하지 않는다. 줄 본문 폭이 360px 이하(휴대폰·마법봉 창)면 첫 줄 대신 둘째 줄 채팅 이름 앞에 보인다(컨테이너 쿼리, 요소를 두 곳에 두고 CSS로 하나만). 2026-10-04 모바일에서 첫 줄에 같이 두면 이름이나 페르소나 중 하나가 'Sa…'·'♥ 김…'로 잘려서 바꿈
- **고정(4번, 2026-10-03)**: ST 최근 채팅의 고정과 **같은 저장소**(accountStorage `pinnedChats`, 키 `char_<아바타>_<파일>.jsonl` / `group_<id>_<파일>.jsonl`, 값 `{ group, avatar, file_name }`)를 읽고 쓴다(`src/pins.js`). 이 확장이 ST 최근 채팅을 가리므로 고정·해제도 로비에서 해야 한다(⋮ 메뉴). 둘러볼 때 맨 위 '고정' 묶음(이름·메시지 수 정렬이면 나머지에 '나머지 채팅' 제목), 검색 결과에는 📌만. `/api/chats/recent`에 `pinned`를 넘기면 서버가 개수 제한과 별도로 맨 앞에 넣어 주므로 오래된 고정 채팅도 보인다(hasMore 는 찾은 고정 수만큼 보정). 지운 채팅은 고정에서 뺀다(ST 는 안 뺌)
  - 함정: ST `PinnedChatsManager`는 목록을 메모리에 캐시하고(시작 시 한 번 읽음), CHAT_RENAMED 때 **캐시로 저장소를 통째로 덮어쓴다**(그 채팅이 ST 캐시에 있을 때). 캐시를 다시 읽게 할 방법이 없어(내보내지 않음) 이 확장에서 바꾼 것을 `changes`에 기록해 두고, CHAT_RENAMED 처리 뒤(setTimeout — 리스너 순서에 기대지 않음) 저장소에 다시 얹는다(이름이 바뀐 고정은 새 이름으로 옮김). ST 최근 채팅 화면(설정 끔)은 새로 고침 전까지 옛 캐시로 보인다
  - 확인: 불러올 개수 4 + 오래된 채팅 고정 → 새로 고침 후에도 '고정' 묶음(4개 + 고정 1), 로비에서 고정한 채팅 이름 바꾸기 → 고정 유지, ST 캐시에 있는 고정 채팅 이름 바꾸기(ST 가 옛 캐시로 덮어씀) → 두 고정 모두 유지, 고정 채팅 삭제 → 고정 목록에서 빠짐
- **캐릭터 고르기**(2026-10-03, 전체/캐릭터/그룹 보기를 대체): 그룹 채팅이 없으면 의미가 없고, 이름 검색·캐릭터별 정렬과 겹치며, 남아 있던 필터 때문에 검색이 고장 난 것처럼 보인 적이 있어 사용자와 상의해 바꿨다. 선택지는 모든 캐릭터·그룹(이름 순, 같은 이름은 아바타 파일 이름 덧붙임, 그룹은 👥). 고르면 `getOwnerChats`로 그 캐릭터의 채팅 **전부**를 따로 불러온다(캐릭터: `/api/characters/chats`, 그룹: `/api/chats/search` 검색어 없음) — 최근 N개 제한과 무관. 검색·대화 내용 검색도 그 캐릭터만. 고르면 선택·대화 내용 검색 결과는 버린다. 같은 채팅이 최근 목록·캐릭터 목록·검색 결과에 따로 있을 수 있어 이름 바꾸기·삭제는 셋 다 맞춘다. 결과가 없으면 [모든 캐릭터에서 찾기](다른 캐릭터 채팅은 일부만 불러와 있어 0개여도 항상 둔다)
- (이전) 보기 필터(캐릭터/그룹)는 **기억하지 않는다**(0.1.0 은 기억했음). 사용자가 '그룹'으로 둔 채 다음에 'sera'를 검색해 0개 → 검색 고장으로 보였다(2026-10-03 사용자 지적). 지금은 필터 때문에 숨은 결과가 있으면 '그룹 채팅 중에는 없습니다. 다른 채팅에서 N개' + [전체 보기]. 저장돼 있던 `filter` 값은 설정 읽을 때 지운다
- 검색·필터·정렬은 **불러온 채팅 안에서만**. 일부만 불러온 상태면 안내 문구 + [모든 채팅에서 검색](`max` 없이 다시 요청)

## 3. 동작 (`src/chat-actions.js`)

| 동작 | 캐릭터 | 그룹 |
|---|---|---|
| 열기 | 존재 확인(`/api/characters/chats simple`) → `unshallowCharacter` → 다른 캐릭터면 `characters[chid].chat = file` 후 `selectCharacterById` 한 번(+ `updateRemoteChatName`), 같은 캐릭터면 `openCharacterChat` → `setActiveCharacter(avatar)` | `group.chats` 포함 확인 → 다른 그룹이면 `chat_id`·`date_last_chat` 저장(`editGroup(…, false)`) 후 `openGroupById` 한 번, 같은 그룹이면 `openGroupChat` → `setActiveGroup` |
| 이름 바꾸기 | `/api/chats/rename` → 마지막 채팅이면 `updateRemoteChatName`(+ 현재 캐릭터면 `#selected_chat_pole`) → 열린 채팅이면 `reloadCurrentChat` → `CHAT_RENAMED` | `/api/chats/rename {is_group}` → `renameGroupChat` → 열려 있으면 다시 불러오기 → `CHAT_RENAMED` |
| 이름 겹침 | 그 캐릭터 폴더 기준 | **모든 그룹** 기준(그룹 채팅 파일은 한 폴더 공유) |
| 삭제 | `/api/chats/delete` → 마지막 채팅이었으면 목록의 같은 캐릭터 남은 채팅 중 최근 것, 없으면 서버에 물어 최근 것, 그것도 없으면 새 이름 → `CHAT_DELETED` | `/api/chats/group/delete` **성공 뒤에** `group.chats`에서 빼고 `chat_id` 옮김 → `editGroup(…, true)` → `GROUP_CHAT_DELETED` |

- ST의 `renameGroupOrCharacterChat`/`deleteCharacterChatByName`/`deleteGroupChatByName`은 실패를 돌려주지 않거나(팝업·토스트만) 실패해도 `group.chats`를 먼저 고치므로 쓰지 않는다
- 열린 채팅은 삭제 불가(선택 모드에서도 체크 불가), 생성·저장 중(`is_send_press`, `isChatSaving`, `is_group_generating`)이면 열기·열린 채팅 이름 바꾸기 막음
- 일괄 삭제는 순차 실행(그룹 정보 저장이 겹치지 않도록), 결과를 '삭제 N, 실패 M'으로 알림

## 4. 시작 화면 끼워 넣기 (`src/welcome.js`)

- ST `openWelcomeScreen`은 `CHAT_CHANGED`·`APP_READY`마다 `.welcomePanel`을 새로 만들어 `#chat`에 append (`welcome-screen.js:226, 315`)
- `#chat`에 `childList` MutationObserver(하위 트리 X) → 붙은 `.welcomePanel`에 `data-st-lobby` 표시 후 끼워 넣기
- ST 목록(`.welcomeRecent > .recentChatList`)과 최근 채팅 설정(톱니)은 CSS로 숨김. ST의 접기(`recentHidden`)는 `.welcomeRecent`째 숨기므로 그대로 동작
- 제목 `.recentChatsTitle`은 `data-i18n="Recent Chats"`라 ST 번역 옵저버가 되돌림 → 속성을 지우고 자식 span에 `chat_lobby.title` 키
- 설정을 바꾸면 시작 화면이 떠 있을 때만 `openWelcomeScreen({ force: true })`로 다시 그림
